## 1. 개요

9/7 Top-3 검색 정확도 실험에서 FAIL의 주원인으로 확인된 청킹 문제(제목만 검출, 본문 분리, 답 잘림)를 고치기 위해 청킹을 새로 만들고(`app/services/pdf_service.py`), 조건별로 검색 정확도를 비교했다.

### 1-1. 공통 실험 조건

- **질의**: `evaluation/questions_checklist.csv` 20개 표준 질의 × 완전문장(A) / 구어체(B) / 키워드형(C) = 60개 (9/7과 동일)
- **검색**: 운영 `rag_service.search()`, `school_id=konkuk`, Top-10 1회 조회. 단, 10/1 커밋(`470b133`)으로 동의어 질의 확장(`synonyms.py`)이 추가되어 **9/7과 검색 조건이 다름**. 점수 비율(0.5/0.5), 후보 수, 최저 점수, 중복 제거 기준은 동일
- **판정 기준**: PASS = 완결된 답이 Top-3 안 / PARTIAL = Top-4~10 / FAIL = Top-10 안에 없음 / EMPTY = 결과 0건 (9/7과 동일)
- **판정 방법 (9/7과 다름)**: 사람이 원문을 대조하던 방식 대신 **정답 키워드 자동 판정**
    - 질문마다 정답 키워드를 정하고, 그 키워드가 **한 청크 안에 모두** 있어야 "완결된 답"으로 인정 (공백 무시)
    - 제목만 있는 청크, 키워드 일부만 맞는 청크, 핵심 수치가 잘린 청크는 자동으로 FAIL
    - Q14(다전공 자격+학점)는 답이 두 섹션에 나뉘어 있어 두 키워드 묶음을 각각 찾아야 정답
    - 스크립트: `scripts/check_questions_auto.py`, `scripts/eval_chunking_experiments.py`

### 1-2. 새 청킹의 주요 변경점 (`pdf_service.py`)

- 표지·목차·쪽머리/쪽번호 제거 (같은 텍스트가 3쪽 이상 위·아래 여백에 반복되면 쪽머리로 판정)
- Upstage `heading1` 대신 규칙으로 제목 판정 (문장 끝, 번호 패턴, 길이, 한글 비율 등)
- 제목 경로(스택)를 모든 청크 앞에 붙임: `[학적변동 > (1) 휴학 > 가) 휴학의 종류]`
- 제목 바로 뒤 본문을 페이지가 바뀌어도 이어서 한 청크로 묶음
- 한 글자씩 띄어 쓴 제목 정규화: `부 전 공` → `부전공`, `(4) 제 적` → `(4) 제적` (E1부터)

### 2-3. 해석

- **Ebase → E0 (+6)**: 제목 경로와 쪽 경계 병합으로 휴학 종류(Q02), 제적 사유(Q05), 계절학기(Q07·Q08)처럼 "제목만 검출되던" 질의가 해결됐다.
- **E1 (정규화)**: 단독으로는 판정 변화 0건. 같은 쪽 청크가 하나만 남는 검색 제약(3-1) 때문에 정규화로 섹션을 더 잘 찾아도 순위에 반영되지 못했다.
- **E2 (섹션 확장, +2)**: 섹션은 맞게 찾았는데 정답 없는 조각만 나오던 Q01-A, Q17-A 해결. 나빠진 질의 없음.
- **E5 (+7, E2 대비)**: 같은 쪽 중복 제거를 우회하자 정규화 효과가 함께 나타나 부전공 신청자격(Q13), 조기졸업(Q15)이 PASS. 다만 새로 PASS가 된 6건이 모두 정확히 3위라 여유가 작다.
- **Emerge (44)**: 20문항에 맞춰 손으로 고른 병합이라 일반화된 성능으로 보기는 어렵다.

| Q20-B | 수강신청 어떻게 해요? | PARTIAL → PARTIAL | 10 → 8 |
| Q20-C | 수강신청 방법 | FAIL → PARTIAL | - → 8 |

### 3-1. 원인 정리: 같은 쪽 청크가 하나만 남는 문제

`rag_service.search()`는 `(doc_id, article, page)`가 같은 결과를 중복으로 보고 하나만 남긴다. 새 청킹은 `article`이 비어 있어 **사실상 쪽마다 청크 1개만** 검색 결과에 남는다.

- Q13-C: 23쪽 `[부전공 > (2) 신청자격]`(정답)이 같은 23쪽 `[부전공 > (3) 신청방법]`에 밀려 제거됨
- Q10: 6쪽 `[수강신청 > 가) 수강신청 한도학점]`(정답)이 같은 6쪽의 다른 수강신청 청크에 밀려 제거됨

E4/E5는 `article`에 섹션 순번을 넣어 이 제거를 섹션 단위로 바꾼 실험이다. 그러나 `article`은 채팅 출처와 LLM 근거에 "제N조"로 표시되는 필드라(`main.py` `build_source_text()`, `answer_service.build_context()`), 존재하지 않는 조항 번호가 사용자에게 보이게 되어 운영에는 쓸 수 없다. 운영 반영은 `search()`의 중복 기준을 청크 ID로 바꾸는 쪽이 맞다 (5장).

### 3-2. E2 → E4/E5에서 나빠진 질의

Q08-B, Q20-B, Q20-C는 같은 쪽 청크가 여러 개 살아남으면서 Top-10 경쟁자가 늘어 정답 순위가 밀렸다.

## 5. 결론 및 추후 개선 방향

1. **새 청킹(제목 경로 + 쪽 경계 병합 + 제목 정규화)을 운영에 반영했다.** 같은 판정 기준에서 32 → 38/60.
    - ⚠️ **부작용**: `search()` 중복 기준을 고치기 전까지는 4-4의 질의(Q01-A·C, Q04-B, Q06-A·B)가 9/7보다 검색이 안 될 수 있다. 같은 쪽에 청크가 여러 개 생기면서 정답 청크가 중복 제거에 걸리기 때문이다.
2. **[선행 필수] `search()` 중복 기준을 청크 ID로 변경 (검색 담당)**: 현재 `(doc_id, article, page)` 기준이라 같은 쪽 청크가 하나만 남는다. 4-4의 PASS→FAIL 6건 중 5건이 이 문제다. 우회 실험(E5)에서 47/60까지 올랐으므로 우선순위가 가장 높다. 변경 범위는 청크 ID를 후보에 담고 중복 키를 `chunk_id`로 바꾸는 정도로 예상된다(추정). 같은 쪽 출처가 화면에 여러 번 보이는 문제는 출처 표시 단계에서 `(doc_id, page)`로 묶어 해결한다. 수정 후 우회 없이 재측정해 운영 수치를 확정한다.
3. **섹션 확장 운영 반영 검토**: 평가에서 나빠진 질의 없이 +2. 검색 결과를 LLM에 넘기기 전에 같은 섹션 조각을 합치는 방식으로 넣을 수 있다.
4. **25쪽 이후 교육과정 부분**: `⊶ 전공교육과정 ⊷` 같은 장식 제목이 학과명을 밀어내 제목 경로가 부정확하다. 학과별 교육과정 질의를 평가에 추가할 때 함께 개선한다.
5. **어휘 불일치**: "복수전공"(질의) ↔ "다전공"(원문) 같은 경우는 동의어 사전(`synonyms.py`)에 추가가 필요하다.
6. **일반화 검증**: 청킹 설계에 쓰지 않은 새 질의 10~20개를 만들어 한 번 평가해 과적합 여부를 확인한다.
