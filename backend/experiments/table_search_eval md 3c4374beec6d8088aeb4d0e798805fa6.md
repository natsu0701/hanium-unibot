## 4. 원인 심층 분석 — 실제 청크 텍스트 대조

검색 결과만으로는 "순위가 밀렸다"는 현상만 보이지만, `extracted.json`의 실제 청크 텍스트를 이미지 원본과 대조한 결과 **순위 문제보다 심각한 정보 소실·왜곡**이 다수 확인됨. 원인은 `table_parser.py`가 첫 행만 헤더로 인식하고, rowspan/colspan을 무시한 채 `zip(headers, cell_texts)`로 순서대로만 매칭하기 때문.

### 4-1. 실패 모드는 두 가지로 구분됨

1. **rowspan 문제 (셀 부족)**
    - 매커니즘: 병합 셀이 첫 행에만 존재하고 후속 행엔 물리적으로 없음 → 후속 행의 셀 개수가 줄어듦
    - 결과: 값이 통째로 소실됨
    
    **원본 표 구조 (병합 셀이 3개 행에 걸쳐 있음)**
    
    ```
    ┌──────────────┬─────────────────────┐
    │  결석 사유     │   공인결석 인정기간     │
    ├──────────────┼─────────────────────┤
    │  병역 관련     │                     │
    ├──────────────┤   실제 참가기간(시간)   │  ← rowspan=3
    │  학술답사 등   │   (3개 행에 병합됨)    │
    ├──────────────┤                     │
    │ 정부기관 행사   │                     │
    └──────────────┴─────────────────────┘
    ```
    
    **실제 HTML 셀 개수**
    
    ```
    1행: [병역 관련] [실제 참가기간(시간)]   ← 셀 2개 (병합 셀 포함)
    2행: [학술답사 등]                      ← 셀 1개 (병합 셀 없음!)
    3행: [정부기관 행사]                    ← 셀 1개 (병합 셀 없음!)
    ```
    
    **파싱 결과 (zip이 헤더 2개 vs 셀 1개를 매칭 → 뒤 헤더는 버려짐)**
    
    ```
    ┌──────────────┬─────────────────────┐
    │  병역 관련     │  실제 참가기간(시간)    │  ✅ 정상
    ├──────────────┼─────────────────────┤
    │  학술답사 등   │        ???          │  ❌ 값 없음 (소실)
    ├──────────────┼─────────────────────┤
    │ 정부기관 행사   │        ???          │  ❌ 값 없음 (소실)
    └──────────────┴─────────────────────┘
    ```
    
    → **셀이 헤더보다 부족**해서 뒤쪽 값이 통째로 사라짐.
    
2. **colspan/서브컬럼 문제 (셀 초과)**
    - 매커니즘: 헤더에 없는 숨은 서브컬럼이 데이터 행에 끼어 있음 → 셀 개수가 헤더보다 많음
    - 결과: 헤더-값이 한 칸씩 밀려 서로 자리를 바꿈 (문법적으로 완결돼 보여 더 위험)
    
    **원본 표 구조 (숨은 서브컬럼이 끼어 있음)**
    
    ```
    ┌───────────┬─────────────────┬──────┬────────┬──────────┬────────┐
    │ 교육과정    │ 교과목명          │이수   │개설학기  │운영목적   │ 교육과정 │
    │ 구분       │                 │대상   │        │          │ 운영방식 │
    ├───────────┼─────────────────┼──────┼────────┼──────────┼────────┤
    │ K-Project │K-Project        │1학년  │ 2학기   │전공분야    │ 희망전공 │
    │           │                 │      │        │전문성향상  │ 탐색 과정│
    ├───────────┼──────────┬──────┼──────┼────────┼──────────┼────────┤
    │ Nano-LAB  │ Nano-LAB │기초1  │2학년  │ 1학기   │전공분야    │∙사제이음 │
    │           │          ├──────┼──────┼────────┤전문성향상  │ 교육 등  │
    │           │          │기초2  │2학년  │ 2학기   │          │        │
    └───────────┴──────────┴──────┴──────┴────────┴──────────┴────────┘
    ```
    
    **파싱 결과 (zip이 헤더 7개 vs 셀 8개 → 뒤로 갈수록 한 칸씩 밀려서 매칭)**
    
    | 교육과정 구분 | 교과목명 | 이수 대상 | 개설 학기 | 운영 목적 | 교육과정 운영 방식 | 비고 |
    | --- | --- | --- | --- | --- | --- | --- |
    | "어드벤처 설계형" K-Project | K-Project (전공선택, 1학점 1시간) | 1학년 | 2학기 | 전공교육 적응력 향상 | ∙ 희망 전공 탐색 과정 | 수강한도 학점에서 제외 |
    | "전공 도제형" Nano-LAB | Nano-LAB (전공선택, 1학점, 1시간) | **기초1** ❌ | **2학년** ❌ | **1학기** ❌ | **전공분야 전문성 향상** ❌ | ∙ 전공 사제이음 교육 |
    | 기초2 | 2학년 | 2학기 | *(값 없음)* | *(값 없음)* | *(값 없음)* | *(값 없음)* |
    | 심화1 | 3학년 | 1학기 | *(값 없음)* | *(값 없음)* | *(값 없음)* | *(값 없음)* |
    | 심화1 | 3학년 | 2학기 | *(값 없음)* | *(값 없음)* | *(값 없음)* | *(값 없음)* |
    | "다학제 융합형" Lego-Convergence (융합 다/부전공) | 융합 다/부전공(Cell교육과정)을 구성하는 전공교과목 | 2~4학년 | 1,2학기 | 융복합 전공교육 강화 | ∙ 전공 블록인 'Cell 교육과정 … | 단일 Cell교육과정 이수 가능 |
    | "사회수요 맞춤형" Micro-Degree | 해당 교육과정을 구성하는 전공교과목 | 3~4학년 | 1,2학기 | 전공 실무역량 강화 | ∙ 산학연계 실무교육과정 | 운영 전공 소속 또는 이수 학생 |
    
    → **셀이 헤더보다 많아서** 뒤 칸들이 전부 한 칸씩 밀려 **엉뚱한 라벨에 붙음**. "운영 목적: 1학기"처럼 문법적으로 멀쩡해 보여서 오히려 더 위험함.
    

### 4-2. 표별 사례

**① 결석 사유표 (rowspan → 값 소실)**

```
결석 사유: 단과대학 학(원)장이 승인한 학술답사, 견학, 현장실습, 교직과목 이수생의 교생실습 참가의 경우
```

"실제 참가기간(시간)"이 8개 행에 걸친 rowspan 셀인데, 후속 7개 행엔 이 값이 아예 없음. "병역으로 결석하면 며칠 인정돼?" 같은 질문엔 이 청크로 답변 불가.

**② 성적 등급표 (rowspan → 존재하지 않는 라벨 생성)**

| 등급 | 평점 |
| --- | --- |
| A+ | 4.5 |
| A | 4.0 |
| B+ | 3.5 |
| B | 3.0 |
| C+ | 2.5 |
| C | 2.0 |
| D+ | 1.5 |
| D | 1.0 |
| F
P
N | 0
 |
| - | Pass
Non-Pass |

```
등급: FPN / 평점: 0
등급: (공란) / 평점: Non-Pass Pass
```

F/P/N 세 등급이 병합 셀로 묶여 있던 것이 파싱되면서 "FPN"이라는 실존하지 않는 등급명이 생성됨. "성적 등급 P는 뭐야?"가 검색에서 밀린 근본 원인 — "P"라는 정확한 형태가 청크 텍스트 어디에도 없음.

**③ 이수학점표 (colspan → 헤더 이름 자체가 오염, 대형 반복 표)**

```
   -----------------------------------------------------------------
1행: 대학 │ 학과 │ 교양 │      전공        │ 다전공* │ 부전공* │ 졸업이수학점
         │     │     ├─────┬─────┬─────┤       │        │
2행:     │     │     │ 전필 │ 전선 │  계  │       │        │
   -----------------------------------------------------------------

table_headers: ["대학", "학과", "(공란)", "교양", "다전공*", "부전공*", "졸업이수학 점"]
대학: 디자인 대학 / 학과: 산업디자인학과 / (공란): 31 / 교양: 14 / ...
```

2단 헤더(대학/학과/교양/전공(전필·전선·계)/다전공/부전공/졸업이수학점)를 1행만 헤더로 인식하면서 컬럼명 자체가 틀림. **순위가 1위로 개선돼도 LLM이 틀린 숫자를 인용할 위험**이 있는 사례. 또한 대학명 자체도 rowspan이라 "경제통상학과", "경찰학과" 등 후속 행엔 소속 대학 정보가 없음 — 검색 실패(4·5위)의 근본 원인.

**④ 특성화 교육과정표 (colspan+rowspan 복합 — 라벨이 서로 자리를 바꿈)**

```
이수 대상: 기초1 / 개설 학기: 2학년 / 운영 목적: 1학기 / 교육과정 운영 방식: 전공분야 전문성 향상 / 비고: (불릿 목록)
```

Nano-LAB 행에만 존재하는 숨은 서브라벨("기초1")이 헤더에 없는 컬럼으로 끼어들면서, 이후 모든 값이 한 칸씩 밀려 **운영 목적·운영 방식·비고가 서로 뒤바뀜**. 문장이 문법적으로 완결돼 보여 이상 징후가 텍스트만으론 드러나지 않음 — 가장 주의가 필요한 실패 유형. 뒤이은 기초2/심화1/심화2 행은 반대로 rowspan 셀이 없어 교육과정구분·교과목명 라벨 자체가 오염되고 운영목적·방식·비고 값이 소실됨 (rowspan+colspan 문제가 한 표 안에 동시 발생).

## 5. 패턴별 분류 종합

| 패턴 | 원인 유형 | 해당 사례 | 위험도 | 문제 유형 | 담당/제안 |
| --- | --- | --- | --- | --- | --- |
| 값 소실 (rowspan 셀이 후속 행에 없음) | rowspan | 결석사유표, 이수학점표(대학명), 교육과정표(기초2~심화2) | 중간 — 근거 부족으로 답변 거부될 가능성 높아 상대적으로 안전 | 파싱 로직 한계 | `table_parser.py` rowspan 대응 |

## 6. 결론

**1) 표 파싱 개선(`html_table_to_text()` 통합)은 방향이 맞고 효과가 있음.**
Top-1 60%, Top-3 70%는 개선 이전(표 청크 검색이 사실상 불가능했던 상태) 대비 뚜렷한 진전이며, 오탐도 0/5로 조문 검색을 해치지 않는다는 것이 확인됨.

**2) 다만 검색 순위 실패(3/10) 이면에는 그보다 심각한 데이터 정합성 문제가 있음.**
청크 텍스트를 직접 대조한 결과, 단순 헤더 인식(`rows[0]`만 헤더)과 rowspan/colspan 미대응이 원인이 되어:

- 값이 통째로 사라지는 경우 (결석사유표, 교육과정표)
- 존재하지 않는 라벨이 생성되는 경우 (성적등급표 "FPN")
- **헤더와 값이 서로 자리를 바꿔 문법적으로 멀쩡한 오답을 만드는 경우** (교육과정표 Nano-LAB 행, 이수학점표 전체)

세 번째 유형이 가장 위험함 — 검색 순위가 정상이어도 LLM이 틀린 정보를 근거로 채택할 수 있기 때문.

**3) 문제는 두 축으로 수렴함.**

- 파싱 로직: `table_parser.py`의 rowspan/colspan 미대응
- 청킹 설계: 대형 반복 표의 행 단위 분리 필요
